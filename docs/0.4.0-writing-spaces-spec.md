# 《伊萨卡手记》0.4.0 写作空间规格

状态：收敛新增实现与人工验收完成，已发布 staging

目标环境：staging（已发布）

最后更新：2026-08-24

## 1. 版本目标

0.4.0 将现有“写作台—主题—成书”的单一路径重构为四个相互衔接、但界面职责独立的写作空间：

- 书桌：添加纸页并持续书写。
- 公告板：把碎片放到白板上，通过空间摆放与拼图机制形成主题。
- 信箱：阅读来信、查看寄件，并从通信情境进入书信写作。
- 书架：陈列和阅读已经装订的成书快照。
- 标题场景：使用已完成的屋顶天空背景，与共享现实时间系统保持一致，并在旅程入口之后依次提供设置与小彩蛋。

底层共享“纸页”和客户端加密能力，不要求四个场景共享同一套页面布局。

## 2. 核心概念

### 2.1 纸页

纸页是可编辑内容的最基本单元，包含标题、正文、一个可空分类、零个或多个标签、创建时间和修改时间。标题、正文与标签随正文一起在浏览器内加密；分类作为工作流元数据保存。

### 2.2 分类

一张纸页最多属于一个分类：

- `碎片`：尚未形成稳定结构的随手记录，也是从书桌进入时的默认分类。
- `主题`：可以直接创建，也可以由公告板拼接结果带回书桌后继续写。
- `书信`：准备寄出的信件草稿；寄出后仍可保留原稿。
- `书籍`：正在写作或编辑的书稿；不要求来源于主题。
- `日记`：按日期持续记录的独立纸页类型，与碎片、主题、书信和书籍平级。
- `未分类`：计算视图，表示分类为空的纸页，不是第六个分类值，也不是标签。

旧版本明确作为碎片创建的纸页在迁移后归入`碎片`，避免既有资料突然进入`未分类`。

### 2.3 标签

标签是用户自定义、可多选、可跨分类的检索词，例如“学术”“伊萨卡手记”。标签不改变内容的工作流状态，也不承担主题、书信或书籍的业务语义。

### 2.4 主题板与主题手稿

公告板中的“主题板”是空间拼接对象，保留题目、说明、碎片成员与布局。它不是书桌分类本身。用户选择“带回书桌继续写”时，系统创建或打开一张分类为`主题`的纸页，并记录其来源主题板；之后编辑纸页不会破坏公告板布局。

### 2.5 书信草稿与寄件

分类为`书信`的纸页是可编辑草稿。用户从来信选择“回信”时，书桌新建书信纸页并保留来源来信日次。执行“寄出”后，信箱寄件箱生成一份不可变的加密快照。0.4.0 的寄出是应用内归档语义，不调用真实邮件服务。

### 2.6 书稿与成书

分类为`书籍`的纸页是可编辑书稿。书稿可以从空白开始，也可以由任意已有内容整理而来；主题不是前置条件。执行“装订并上架”后，书架生成不可变的加密成书快照。删除书架快照不删除原书稿。

## 3. 信息架构

### 3.1 房间入口

- 点击桌面：进入书桌，默认`按分类 / 碎片`。
- 点击公告板：进入主题拼接白板。
- 点击信箱：进入收件箱，允许切换到寄件箱。
- 点击书架：进入书架陈列。
- 点击房间台灯或走廊壁灯：分别切换对应场景的明暗；两盏灯互不联动，刷新后保持当前设备上的选择。
- 每个功能层只保留一处清晰的“返回房间”，不叠加两层全局导航。

### 3.2 书桌

书桌采用“浏览栏 + 编辑纸面”的双栏结构，不设置永久的“关联素材”右栏。

浏览栏顶部提供`＋ 新纸页`和两种互斥浏览模式：

- 按分类：未分类、碎片、主题、书信、书籍、日记；显示数量与当前选择。
- 按标签：显示实际存在的标签；结果卡片附分类徽记。

编辑区提供标题、正文、分类选择、标签编辑、保存状态与上下文动作。上下文动作随分类出现：主题纸页可查看来源主题板，书信纸页可寄出，书籍纸页可装订上架。删除放入二次确认菜单，不与主动作争夺视觉权重。

### 3.3 公告板

公告板采用“主题板目录 + 素材托盘 + 有边界画布”的专属布局：

- 主题板目录负责新建、切换和显示碎片数量。
- 素材托盘只展示可用的`碎片`纸页。
- 画布支持加入、移除、拖动、层级、自动整理、拼图吸附与保存布局。
- 主完成动作是`带回书桌继续写`，创建或打开来源关联的主题纸页。
- 公告板不出现`按分类 / 按标签`切换。

### 3.4 信箱

信箱采用通信语义，不复用书桌侧栏：

- 收件箱：系统旅程来信，显示未读/已读和当前抵达信件。
- 寄件箱：已经寄出的不可变快照。
- 阅读来信时提供`回信`；新建信件提供`写一封信`，两者都进入书桌的书信草稿。
- 阅读寄件时提供`由此建立新草稿`，不直接修改已寄出快照。

### 3.5 书架

书架采用成品陈列语义，不复用书桌侧栏：

- 封面网格呈现已经装订的书籍，阅读区呈现完整快照。
- 空状态可以直接`开始一本书`，进入书桌空白书稿。
- 成书来源可以为空白书稿、普通纸页整理或主题材料；主题不是必选项。
- 已上架内容不原位编辑；需要修改时从书稿继续写，或由快照建立新的书稿。

### 3.6 标题入口、设置与小彩蛋

- 标题页操作从上到下为`开始旅程 / 继续旅程`、`设置`、`小彩蛋`，三项在目标桌面高度内保持可见。
- 设置首期支持`简体中文`与`English`即时切换，语言偏好保存在当前浏览器；语言包按独立词典注册，后续新增语言不需要改写业务模块。
- 翻译只作用于应用导航、按钮、状态、系统文案和无障碍名称，不翻译用户标题、正文、标签、书信或成书内容。
- 小彩蛋以旅程里程碑面板呈现已解锁与未解锁项目，并在新里程碑发生时显示克制的浮层提示。
- 因正文只在客户端解密，内容型里程碑由客户端从明文归档计算，再以幂等请求写入当前账户；服务端只接受固定的里程碑键。

## 4. 核心流程

### F1：普通书写

房间桌面 → 书桌默认碎片 → 新纸页 → 写标题与正文 → 设置分类/标签 → 保存 → 按分类或标签重新找到。

### F2：拼接主题

书桌碎片 → 公告板 → 新建/选择主题板 → 放入并排列碎片 → 保存布局 → 带回书桌 → 主题纸页继续写。

### F3：通信

房间信箱 → 打开来信 → 回信 → 书桌书信草稿 → 寄出 → 信箱寄件箱阅读快照。

### F4：成书

书桌新建/打开书籍纸页 → 持续写作 → 装订并上架 → 书架阅读不可变快照。

### F5：设置与里程碑

标题页 → 设置 → 切换中英文 → 即时更新并在刷新后保持；标题页 → 小彩蛋 → 查看账户里程碑 → 完成对应行为 → 新里程碑提示并持久化。

### F6：场景灯光

房间 → 点击台灯 → 桌面与周边出现暖光 → 再次点击恢复原有时段明暗；门外走廊的壁灯遵循同一交互，但保存独立状态。灯具在布置模式中仍只负责移动，不误触开关。

## 5. 数据与兼容规则

- 现有`journal_entries`增加可空分类、来源主题板和来源来信日次；旧纸页迁移为`碎片`。为兼容 0011 的四类数据库约束，0012 另增可空`writing_category`作为新 Worker 的权威分类，并在旧`category`列保留可回滚镜像；`日记`在旧列镜像为`碎片`。
- 标签封装在纸页加密载荷中，服务端不需要读取标签文本；筛选由已解密的客户端列表完成。
- 现有`topics`及其碎片布局继续作为公告板数据，新增与主题纸页的可选来源关系。
- 现有旅程来信和已读状态原样保留；新增寄件快照表。
- 现有`books`保留为成书快照，新增来源书稿字段；创建成书不再要求非空主题。
- 所有记录必须按当前账户隔离；来源 ID 必须同时验证所有权和适用分类。
- 新增账户级`achievements`表，里程碑解锁使用固定键和幂等写入；导出与删除账户覆盖新增分类元数据、来源关系、寄件、成书和里程碑数据。
- 灯光状态属于当前设备的场景偏好，使用版本化浏览器存储键独立于房间布局保存；存储不可用时仍支持当前会话切换，不进入账户导出。

## 6. 视觉与交互原则

- 基调为“70% 安静编辑室 + 30% 游戏化仪式”。
- 延续暖纸色、深海军蓝墨色、铁锈红强调色；正文使用中文衬线字体，控件与状态使用无衬线字体。
- 书桌最安静，公告板的物理感最强；信箱强调对应关系，书架强调陈列与阅读。
- 标题场景保持同一屋顶机位和中央 UI 安全区：05:00–11:59 使用清晨图；12:00–16:59 复用清晨图并施加克制的暖色调；17:00–21:59 使用黄昏图；22:00–04:59 使用深夜图与独立星点层。阶段切换复用房间的同一时间服务，不创建第二套时钟。
- 房间和走廊开灯时复用现有灯具图层，以局部金色光晕强化灯泡、桌面、墙面和信箱附近；关灯后回到现实时间系统的基础光照，不用全屏泛白代替灯光方向。
- 避免以巨大罗马数字、重复顶栏或装饰性空白代替真实功能。
- 桌面端优先，验收尺寸为 1024×720、1440×900、1920×1080；1024 宽度下允许收紧间距，但核心动作不可被遮挡。
- 键盘可以到达主要入口、浏览模式、列表项、表单和对话框；焦点可见；保存、失败、空状态由文字说明，不只依赖颜色。

## 7. 非目标

- 不接入真实电子邮件、联系人或公开分享。
- 不实现多人协作、同步编辑或主题板实时联机。
- 不实现移动端专用布局。
- 不自动部署 staging 或 production。
- 不在本版本重做房间原画或生成新的位图资产；标题场景只提升此前已生成并确认采用的三张背景。

## 8. 验收条件

### AC-01 纸页与分类

可创建、修改、删除和刷新后恢复纸页；分类可在五类与空值之间切换；`日记`与碎片、主题、书信、书籍平级；`未分类`只包含空分类；进入书桌默认显示碎片。

### AC-02 标签

一张纸页可拥有多个去重标签；`按标签`只展示真实标签并可跨分类筛选；结果显示分类徽记；标签文本只存在于加密内容中。

### AC-03 公告板

可独立进入公告板，选择主题、加入碎片、拖动/整理并持久化布局；可把结果带回书桌形成来源关联的主题纸页；公告板不显示书桌分类导航。

### AC-04 信箱

可独立查看收件箱和寄件箱；从来信回信会进入书桌书信草稿；寄出生成不可变快照且刷新后仍存在；不触发外部发送。

### AC-05 书籍

可从空白创建书稿；无需主题即可装订上架；成书刷新后仍可阅读且不随原书稿修改；书架不显示书桌分类导航。

### AC-06 兼容、隐私与账户边界

迁移后旧碎片、主题布局、来信状态和成书仍可读；新内容保持客户端加密；跨账户 ID 不能读取或建立来源关系；导出和删除账户包含新增数据及里程碑。

### AC-07 界面与可访问性

四个写作场景在三种目标桌面尺寸下无横向溢出、关键按钮遮挡或不可恢复的空状态；主要流程可用键盘完成；对话框可关闭并正确恢复焦点。标题场景在清晨、下午、黄昏、深夜四个阶段使用预期背景，旅程、设置、小彩蛋和底部操作保持清晰可读。

### AC-08 质量门槛

单元测试、Worker 集成测试、类型检查和 dry-run build 全部通过；真实浏览器完成核心流程、刷新持久化、中英文切换、里程碑及三档标题页视觉验收。0011 与此前 Worker 已发布 staging；本轮 0012 与新版 Worker 必须在产品负责人另行授权后发布，production 仍需另行授权。

### AC-09 设置与小彩蛋

标题页的设置和小彩蛋位于旅程入口之后；中英文可即时、可逆切换并在刷新后保持；新增语言可通过注册词典扩展；小彩蛋正确区分锁定和已解锁里程碑，新解锁只写入一次，刷新与重新登录后仍存在。

### AC-10 房间与走廊灯光

房间台灯和走廊壁灯均可通过鼠标及原生按钮键盘操作切换；开、关状态有清晰但克制的视觉差异、动态操作名称和`aria-pressed`反馈。两盏灯分别持久化，场景往返与刷新后保持；布置模式只移动台灯，不改变其明暗。
