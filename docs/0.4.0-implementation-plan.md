# 《伊萨卡手记》0.4.0 实现计划

状态：收敛新增已完成并发布 staging，待已登录账户业务复查

目标环境：staging（已发布）

规格来源：`docs/0.4.0-writing-spaces-spec.md`

## 1. 交付策略

采用纵向切片完成数据、API、界面与验证，保留 0.3 数据兼容。先建立纸页分类与来源关系，再分别完成书桌、公告板、信箱和书架，最后补齐日记分类、语言设置和里程碑并执行整体验收。此前 0.4.0 基线已发布 staging；本轮收敛新增项已获授权并发布 staging，production 仍需另行授权。

## 2. 数据模型与 API

### S1 纸页工作流元数据

- 新增迁移，为`journal_entries`加入可空`category`、`source_topic_id`、`source_letter_day`。
- 迁移既有纸页为`fragment`；0011 基线 API 接受`fragment | theme | letter | book | null`，0012 收敛版本扩展为`fragment | theme | letter | book | journal | null`。
- 将标签作为加密载荷中的`tags: string[]`保存；旧载荷缺少标签时按空数组读取。
- entries 列表、详情、导出返回分类和来源元数据；创建/更新校验来源所有权。

### S2 寄件快照

- 新增`sent_letters`表：ID、账户、可空来源纸页、加密快照、加密版本、寄出时间。
- 新增寄件列表、详情和创建 API；创建时验证来源纸页属于当前账户且分类为`letter`。
- 将寄件纳入隐私导出与账户级联删除。

### S3 成书来源重构

- 为`books`增加可空`source_entry_id`。
- 创建成书允许空主题来源；使用书稿来源时验证账户和`book`分类。
- 0.4 UI 只创建、读取和移除快照，不原位编辑成书正文。
- 保留旧书记录与旧来源快照解码能力。

## 3. 客户端切片

### S4 书桌

- 将旧写作台改为单一书桌视图：顶栏、浏览栏、纸面编辑区。
- 浏览栏提供`按分类 / 按标签`，默认`按分类 / 碎片`。
- 编辑器支持分类选择、标签录入与分类上下文动作。
- 保留自动保存/显式保存状态、删除确认和浏览器端加解密。

### S5 公告板

- 从书桌壳层中拆出专属公告板视图。
- 保留现有主题数据、拼图片与布局保存能力，改为主题目录、素材托盘和画布布局。
- 素材托盘只接受碎片分类。
- 新增“带回书桌继续写”：组合主题与碎片文本，在客户端创建主题纸页并记录`source_topic_id`；已有来源纸页时直接打开。

### S6 信箱

- 新建专属信箱视图，包含收件箱、寄件箱和阅读区。
- 将现有旅程来信阅读能力接入收件箱。
- 新增“写一封信”“回信”和“寄出”流程；寄出快照由客户端加密。

### S7 书架

- 重做空状态、封面网格和阅读区文案，移除“必须先有主题”的暗示。
- 新增“开始一本书”进入空白书稿。
- 书稿编辑器提供“装订并上架”，直接以当前书稿创建加密快照。

### S8 场景路由与共享视觉

- 房间四件物品分别进入四个视图，返回动作统一回房间。
- 共享颜色、字体、边框、焦点与反馈 token，不共享不合适的信息架构。
- 处理 1024×720、1440×900、1920×1080 三档桌面布局。

### S9 标题场景与现实时间

- 将已生成的屋顶天空清晨、黄昏、深夜图提升到`src/client/assets/scenes/title/`正式资源目录，并保留来源与哈希证据。
- 标题页读取`renderSceneTime`维护的`data-time-phase`：清晨/下午复用日景，下午施加轻微暖色调；黄昏和深夜使用各自重光照版本。
- 图片只承担装饰背景，标题、旅程按钮、账户操作继续使用语义 HTML；黄昏关闭星点层，深夜保留星点层。

### S10 标题菜单、语言与里程碑

- 在旅程入口之后纵向加入设置和小彩蛋，保持标题场景在三档目标尺寸中的中心层级与可见性。
- 建立独立语言注册表和词典，首期支持`zh-CN`与`en`，保存浏览器偏好；动态文案通过统一翻译层处理，用户内容明确跳过。
- 建立账户级里程碑 API、固定键白名单和幂等写入；客户端基于解密后的账户归档计算达成条件，面板展示锁定/解锁状态并在首次解锁时提示。

### S11 日记分类兼容扩展

- 新增 0012 迁移，为`journal_entries`加入支持五类的`writing_category`，并创建`achievements`表。
- 由于 SQLite 不能直接放宽 0011 的列级 CHECK，保留旧`category`作为回滚镜像：日记在旧列写为`fragment`，新 Worker 始终优先读写`writing_category`。
- 书桌分类导航、编辑器选择、筛选、导出、账户删除和测试全部纳入`journal`。

### S12 房间与走廊灯光

- 将房间台灯和走廊壁灯从静态装饰改为语义按钮，使用统一`toggleState`配置声明状态键、默认值和开关文案。
- 新增版本化场景状态存储，与房间布局分离；运行时负责切换、场景级状态、`aria-pressed`和动态提示，渲染器只同步 DOM 状态。
- 复用正式灯具素材，以 CSS 局部暖光表达开启状态；房间光照聚焦桌面，走廊光照聚焦门边和信箱，并遵守 reduced-motion。
- 台灯在探索模式负责开关，在布置模式仍只负责拖动和方向键调整，避免同一次操作触发两个意图。

## 4. 验证计划

### 自动化

- 单元：分类/未分类规则、标签归一化、筛选、上下文动作、带回主题、寄出、装订载荷。
- Worker 集成：迁移、CRUD、所有权、来源校验、空主题成书、寄件、导出、账户删除。
- 回归：旧纸页、旧主题画布、旅程来信、旧书、客户端加密迁移。
- 工程：`npm test`、`npm run test:integration`、`npm run check`、`npm run build`。

### 真实浏览器

- 依次完成普通书写、主题拼接、通信、成书四条核心流程。
- 每条流程执行刷新恢复，并检查错误、空状态、返回房间与焦点。
- 在 1024×720、1440×900、1920×1080 截图审阅层级、密度和溢出。
- 固定清晨、下午、黄昏、深夜四个阶段审阅标题页的资源映射、文字对比度、按钮可见性和同机位一致性。
- 在标题页往返切换中英文并刷新，确认用户内容不被翻译；打开小彩蛋并触发首篇日记，确认提示、计数和刷新持久化。
- 分别切换房间台灯与走廊壁灯，检查开关视觉、动态中英文名称、`aria-pressed`、场景往返与刷新保持；在布置模式点击台灯确认不会误切灯光。

## 6. 风险与控制

- 加密载荷兼容：归一化解密结果，缺失`tags`按空数组处理，不提升加密版本。
- 来源关系漂移：服务端校验账户和分类；删除来源后快照保留，编辑入口降级为新草稿。
- 大规模 UI 重排回归：保留稳定 DOM 行为边界，按场景逐一验收，不一次性替换加密和旅程模块。
- 1024 高度不足：内容区独立滚动，固定头部控制在单层，关键动作留在可见工具栏。
- 旧 API 兼容：旧请求缺少分类时仍按`fragment`处理；旧书快照继续解码。
